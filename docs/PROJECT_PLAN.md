## 1. الفكرة باختصار

وكيل ذكاء اصطناعي يرصد ويحلل تلف الجدران الطينية في حي الطريف (الدرعية) من الصور:
يحدد نوع التلف ومكانه (تشققات، تساقط الطلاء، تآكل رطوبي...)، ويرسم خريطة تلف موحدة بمفتاح ألوان ثابت،
ويقترح المعالجة والمواد والأدوات من قاعدة معرفة موثقة بمراجعها، ويقارن صور الجدار عبر الزمن لرصد تطور التلف،
ويوضح الحالات التي تحتاج فحصًا ميدانيًا، ويخفي وجوه الأشخاص تلقائيًا.

**المبدأ الحاكم (من شريحة التحدي 15): الوكيل يقترح، والأخصائي يقرر.** لا توصية نهائية دون اعتماد مختص.

**خارج النطاق:** مراقبة الزوار أو تحليل سلوكهم عبر الكاميرات.

## 2. قواعد غير قابلة للتفاوض

1. **لا اختراع مراجع ولا أرقام دقة.** أي رقم دقة يُعرض لازم يكون محسوبًا على صور حقيقية معتمدة من مختص (`scripts/evaluate.py`).
2. **كل بيانات أو نماذج وهمية/اصطناعية تُوسم بوضوح** في الكود والواجهة والتقرير (`mock`، `heuristic_uncalibrated`، `model_synthetic_only`).
3. **الخصوصية:** إخفاء الوجوه قبل أي تحليل أو تخزين. الصورة الأصلية لا تُحفظ. لا تتبع للأشخاص.
4. **المعالجة من المكتبة المغلقة فقط** (`knowledge_base/*.json`)، مع المصدر والصفحة ومقتطف حرفي. التلف غير المؤكد لا يحصل على توصية.
5. **لا ننتقل لمرحلة تالية** إذا كان فيها خطأ يؤثر على الدقة.
6. **التشغيل محلي**؛ لا تُرسل صور الجدران لخدمات سحابية دون موافقة.
7. بعد كل مرحلة يُكتب: ما أُنجز، الملفات، الافتراضات، طريقة التشغيل، الاختبارات، الأسئلة المفتوحة، القيود.

## 4. ما تم بناؤه حتى الآن

- **الخلفية (backend):** FastAPI + SQLAlchemy (SQLite افتراضيًا، PostgreSQL عبر Docker) + وكيل LangGraph.
- **الرؤية:** فحص الجودة، إخفاء الوجوه، ثلاثة كواشف قابلة للتبديل (`heuristic` / `mock` / `synthetic_model`، و`model` جاهز لنموذج حقيقي)،
  المحاذاة والمقارنة الزمنية، رسم الخريطة.
- **التحديد الذكي:** محول SAM 2 مع بديل GrabCut. ⚠️ لم يُجرَّب على أوزان SAM 2 الحقيقية بعد.
- **النموذج الاصطناعي:** مولّد صور بتسميات لخمسة أنواع تلف + مصنّف بكسلات. نتائجه في `docs/synthetic_eval.json`
  **تقيس تقليد المولّد فقط وليست دقة على الطريف.**
- **قاعدة المعرفة:** 8 معالجات من مصدر واحد قُرئ فعلًا: NPS *Preservation Brief 5: Preservation of Historic Adobe Buildings* (1978). كلها «غير معتمدة».
- **الواجهة:** React + TypeScript + Konva، عربية RTL، 9 صفحات (لوحة التحكم، رفع، خريطة، مراجعة، معالجات، مقارنة، تقارير، معرفة، سجل).
- **المخرجات:** تقرير HTML قابل للطباعة PDF، وسجل تعديلات كامل.
- **الاختبارات:** 35 اختبارًا (`python -m pytest -q tests`).

## 5. طريقة التشغيل

### المتطلبات
Python 3.11+، Node 20+، Git. (على Windows استخدم PowerShell.)

### الخلفية
```bash
git clone https://github.com/11mayarrr/heritage-conservation-copilot.git
cd heritage-conservation-copilot
git checkout mvp                      # إلى أن يُدمج PR #1
python -m venv .venv
# Windows:  .venv\Scripts\Activate.ps1      macOS/Linux:  source .venv/bin/activate
pip install -r requirements.txt
cd backend
python -m uvicorn app.main:app --reload --port 8000
```
تحقق: افتح http://localhost:8000/api/health و http://localhost:8000/docs

### الواجهة (نافذة طرفية ثانية)
```bash
cd frontend
npm install
npm run dev
# افتح http://localhost:5173
```

### صور للتجربة
```bash
python scripts/make_synthetic_samples.py      # يكتب sample_data/synthetic/ (صور مرسومة، ليست جدرانًا حقيقية)
```

### تبديل الكاشف
| المتغير | المعنى |
|---|---|
| `HCC_DETECTOR=heuristic` | الافتراضي: قواعد OpenCV غير معايرة |
| `HCC_DETECTOR=mock` | مناطق وهمية للعرض تُظهر كل الألوان |
| `HCC_DETECTOR=synthetic_model` | نموذج مدرّب على بيانات اصطناعية (`python scripts/train_synthetic.py` لإعادة التدريب) |
| `HCC_DETECTOR=model` + `HCC_MODEL_WEIGHTS=...` | لنموذج حقيقي لاحقًا |

### SAM 2 (اختياري)
```bash
pip install -r requirements-sam2.txt
python scripts/download_sam2.py tiny
# PowerShell:
$env:HCC_SEGMENTER="sam2"
$env:HCC_SAM2_CHECKPOINT="C:\path\to\models\sam2.1_hiera_tiny.pt"
$env:HCC_SAM2_CONFIG="configs/sam2.1/sam2.1_hiera_t.yaml"
python -m uvicorn app.main:app --port 8000      # في نفس النافذة التي ضبطت فيها المتغيرات
```
ثم تأكد أن `/api/health` يعرض `"kind": "sam2"`. إن ظهر `grabcut` اقرأ `segmenter_fallback_reason`.

### Docker
```bash
docker compose up --build          # الواجهة 8080، API 8000، PostgreSQL
```

### الاختبارات
```bash
python -m pytest -q tests
cd frontend && npm test && npm run build
```

### مشاكل شائعة (Windows)
- **`uvicorn` غير معروف:** استخدم `python -m uvicorn` داخل البيئة المفعلة.
- **`[Errno 10048]` المنفذ مشغول:** خادم سابق ما زال يعمل. `netstat -ano | findstr :8000` ثم `taskkill /PID <الرقم> /F`،
  أو شغّل على `--port 8001` واكتب في **نافذة الواجهة** قبل `npm run dev`: `$env:VITE_API_TARGET="http://127.0.0.1:8001"`.
- **متغيرات البيئة** (`$env:...`) لا تنتقل بين نوافذ PowerShell.

## 6. القيود المعروفة الآن

- الكاشف الافتراضي لا يصنف تقشر الطلاء ولا فقدان الأجزاء ولا تآكل الحواف، وقد يخلط التشققات بالفواصل والظلال.
- النموذج الاصطناعي لم يرَ جدارًا حقيقيًا؛ أداؤه على الطريف غير معروف ومتوقع أن يكون ضعيفًا.
- درجات الثقة كلها غير معايرة.
- قاعدة المعرفة مرجع أمريكي عام 1978 عن الأدوبي، وليست خاصة بالعمارة النجدية.
- الشبكة المرجعية مؤقتة (6×4)، والمساحة نسبة من الصورة لا بالمتر.
- لا تسجيل دخول حقيقي؛ اسم المختص يُكتب في الواجهة.
- كاشف الوجوه Haar يفوت الوجوه الصغيرة والجانبية.

### 7.1 مسودة بروتوكول التصوير (لـ B1)
- الجدار كاملًا في الإطار، والكاميرا موازية له قدر الإمكان (ميل أقل من 15°).
- إضاءة منتشرة (صباحًا أو وقت الظل)، بدون فلاش، وبدون ظلال حادة.
- علامة ArUco مطبوعة (مثلًا 10×10 سم) ملصقة على الجدار لكل صورة، لأجل F1.
- لوحة ألوان مرجعية إن توفرت، لتوحيد الألوان بين الزيارات.
- نفس الموقع والارتفاع في كل زيارة (علامة على الأرض أو صورة GPS)، لأجل المقارنة الزمنية.
- صورة كاملة + صور مقربة للمناطق المتضررة.
- تسمية الملف: `<رقم الجدار>_<YYYYMMDD>_<رقم>.jpg`.
- تجنب تصوير الزوار؛ والإخفاء التلقائي يبقى خط حماية إضافيًا.

## 8. أفكار إبداعية تزيد قيمة المشروع فعلًا

مرتبة حسب أثرها على معايير التحكيم وسهولة تنفيذها:

1. **القياس الحقيقي بدل النسب (F1، F3):** علامة ArUco صغيرة تحوّل الخريطة إلى أرقام هندسية (م²، طول وعرض التشقق بالمم).
   هذا يجعل المواد والكميات في الخطوة 6 قابلة للتقدير، ويجعل المقارنة الزمنية تقول «زاد التشقق 4 سم» بدل «زاد».
2. **مؤشر خطورة قابل للتفسير (G1):** درجة لكل جدار تجمع نوع التلف ومساحته وموقعه (قرب الأساس أو الحواف) وسرعة تطوره،
   مع جملة تشرح سببها. يساعد إدارة الموقع على ترتيب أولويات الترميم. القواعد تُكتب وتُعتمد من مختص.
3. **التعلم النشط (D5):** بدل أن يراجع المختص كل شيء، النظام يقدّم له أولًا المناطق التي هو أقل يقينًا منها،
   فيتحسن النموذج بأقل جهد بشري. هذا يحول وقت المراجعة إلى بيانات تدريب.
4. **ثقة معايرة وصادقة (D4):** النموذج يقول «لا أعرف» عندما لا يعرف، ويحيل للمختص. يخدم معيار الدقة مباشرة ويطابق قرار «لا: يُستشار المختص» في الشريحة 15.
5. **تصوير موجَّه للزيارات المتكررة (G3):** وقت التصوير تظهر الصورة السابقة شفافة فوق الكاميرا لتطابق الزاوية،
   فتصبح المقارنة الزمنية أدق بكثير.
6. **التوأم الرقمي للجدار (G4، G5):** تجميع عدة صور في صورة مستوية واحدة للجدار الطويل، ثم خريطة للحي تلوّن كل جدار حسب حالته.
7. **دمج الحراري (G6):** الشريحة 15 تذكر الصور الحرارية كمدخل اختياري. الرطوبة تظهر حراريًا قبل أن تظهر بالعين،
   فدمجها يرفع ثقة تصنيف «التآكل الرطوبي». تبقى اختيارية ولا يتوقف النظام بدونها.
8. **«لماذا؟» لكل قرار (G9):** بجانب كل منطقة: مقتطف مكبّر من الصورة، والكاشف الذي اقترحها، ودرجة الثقة ومصدرها، والمرجع الحرفي للمعالجة.
9. **وضع ميداني (G8):** تطبيق ويب يعمل دون إنترنت في الموقع، مع ملاحظات صوتية تُكتب نصًا محليًا.
10. **اعتماد مزدوج (G10):** الحالات عالية الخطورة تحتاج مختصين اثنين، وكل شيء في السجل.

## 9. الداتا سيت: ما هو متاح فعلًا

> **تنبيه:** لا توجد داتا سيت عامة معروفة لجدران الطريف. الداتا العامة تصلح **للتدريب المسبق** (خاصة للتشققات) فقط،
> والتقييم النهائي **يجب** أن يكون على صور حقيقية من الطريف معتمدة من مختص.
> تحقق من الترخيص قبل الاستخدام (C1). ما يلي تحققنا منه من صفحات المصادر في 2026-11-21، وما لم نتحقق منه مكتوب صراحة.

**طرق لزيادة البيانات دون اختراع نتائج:**
- **جمع ميداني وفق البروتوكول (B1–B3)**، وهو الأهم.
- **مراسلة** مؤلفي SYCrack، والجهة المسؤولة عن الطريف، ومنظمي التحدي لطلب صور أو مسرد تلف.
- **صور مرخصة علنًا** للدرعية والعمارة الطينية النجدية (مثل ويكيميديا كومنز، مع التحقق من ترخيص كل صورة)، وتُعلَّم داخل التطبيق.
- **Copy-paste augmentation (C3):** قص تلف حقيقي معلَّم ولصقه على جدران سليمة بإضاءات مختلفة.
- **التعلم النشط (D5)** لتقليل عدد الصور التي يحتاج المختص تعليمها.

## 11. طريقة عمل الفريق

1. **ابدأ من نقطة الاستئناف** في أعلى هذا الملف، واختر مهمة ☐ ليس لها مسؤول، واكتب اسمك عليها.
2. **فرع لكل مهمة:** `git checkout -b <رمز-المهمة>-<وصف>`، مثل `B1-capture-protocol`.
3. **لا تعمل push مباشرة على `main`.** افتح PR واطلب مراجعة من عضو آخر.
4. **قبل الـ PR:** `python -m pytest -q tests`، وإن غيرت الواجهة `cd frontend && npm test && npm run build`.
5. **في نفس الـ PR حدّث هذا الملف:** حالة المهمة، ونقطة الاستئناف، وسطرًا في سجل التحديثات.
6. **قرارات تغير الهدف أو المعايير** تُناقش مع الفريق وتُكتب في القسم 12.
7. **لا ترفع** صورًا غير مرخصة، أو صورًا فيها وجوه، أو مفاتيح وكلمات مرور.
